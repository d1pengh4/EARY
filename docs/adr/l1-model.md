# ADR: L1 추출 모델 — Groq `qwen/qwen3.8-27b`

- 날짜: 2026-10-24
- 상태: 채택 (Cerebras는 키 확보 후 같은 벤치로 비교 예정)
- 관련: ARCHITECTURE.md §7.5, §19 Q1

## 배경
코드 기본값이던 `llama-3.3-70b-versatile`은 2026-10-24 기준 Groq 모델 목록에 없다. 쓸 수 있는 텍스트 모델은 `openai/gpt-oss-20b`, `openai/gpt-oss-120b`, `qwen/qwen3.8-27b`.

## 벤치 (`apps/server/test/l1-bench.ts`, `BENCH_GAP_MS=6500`)
입력: 대본 문장 + 실제 RTZR 출력 형태("2026 현제 4만 8271호", "범주에") + 대본 밖 문장 2개(건강보험 환급, 서류 기한). 8문장 × 2회.

| 모델 | 첫 엔티티 p50 / p95 | 재현율 | 인용 유효 | 빈 응답 | 오류 |
|---|---|---|---|---|---|
| **qwen/qwen3.8-27b** | **522 / 785ms** | **87%** | 100% | 2 | 0 |
| qwen/qwen3.8-27b (`reasoning_effort: none`) | 538 / 911ms | 87% | 100% | 2 | 0 |
| openai/gpt-oss-20b (`reasoning_effort: low`) | 909 / 1368ms | 80% | 100% | 0 | 0 |
| openai/gpt-oss-120b (`reasoning_effort: low`) | 1064 / 1538ms | 80% | 100% | 2 | 0 |

- gpt-oss는 추론 토큰을 먼저 내서 첫 엔티티가 늦다.
- 모든 모델에서 "첫 엔티티 ≈ 전체 시간"이다. 출력이 짧아 스트리밍 이득이 작다. 흘려 받기는 유지하되 지연은 모델 속도가 좌우한다.

## 한도 (무료 등급, 응답 헤더 실측)
- 모델별 **분당 8,000 토큰**, **하루 1,000 요청**
- 호출 1회 ≈ 600~800 토큰 → 분당 약 10회. 시연 1회(상대 발화 7개)는 들어가지만, 1분 안에 연속 리허설하면 429가 난다.
- 대응: 429면 `x-ratelimit-reset-tokens`만큼 L1을 쉬고, 그동안 L0 + D1만으로 동작한다(§15). 8자 미만 발화는 L1을 부르지 않는다.
- 본 시연 전에는 유료 등급 전환이나 Cerebras 키를 예비로 확보하기를 권한다.

## 결정
L1 기본 모델 = Groq `qwen/qwen3.8-27b`. `.env`의 `L1_MODEL`로 바꿀 수 있다.

## 추가 (2026-10-24): 예비 공급사
- Cerebras: 결제 수단 등록이 필요해서 보류. 체인 코드는 준비됨 (`CEREBRAS_API_KEY`가 생기면 자동으로 켜짐)
- **Gemini (AI Studio 무료 등급) `gemini-flash-lite-latest`**
  - 보드 에이전트 체인의 마지막 예비로 채택: Groq gpt-oss-120b → gpt-oss-20b → Gemini. 도구 호출 1.0~1.6s, 검색을 먼저 하려는 행동이 좋았다.
  - 비교: `gemini-3.5-flash-lite`는 검색 없이 바로 "사기 의심"으로 판정(근거 없는 단정), `gemini-3.1-flash-lite`는 3.6s, `gemini-3.8-flash`는 2분 넘게 응답 없음.
  - **L1에는 넣지 않음:** 스트리밍 추출 첫 엔티티 3.5s, 다음 호출은 4s 제한 초과. L1은 Groq만 쓰고, 막히면 L0 + D1으로 버틴다.
  - 주의: 무료 등급은 입력이 Google 제품 개선에 쓰일 수 있다. 실제 사용자 통화에 쓸 때는 고지하거나 유료 등급을 쓴다.
